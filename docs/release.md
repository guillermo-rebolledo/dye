# Releasing Dye

A first submission has roughly forty one-shot steps, several of them irreversible: a
bundle identifier cannot be changed once a build is uploaded, and an app name is
reserved. This is the repeatable part. The full 116-item audit checklist is at the end
of [`docs/audits/app-store-readiness.md`](audits/app-store-readiness.md); this file is
what you work every time.

## Versioning

- `MARKETING_VERSION` is the user-visible semantic version. Bump it by hand in both
  build configurations in `FilmApp.xcodeproj/project.pbxproj` and record the change in
  `CHANGELOG.md`.
- `CURRENT_PROJECT_VERSION` is a monotonic integer. CI passes `github.run_number`, so
  it increments on every build without anyone remembering to. The value committed in
  `project.pbxproj` is only the local-build fallback.
- Tag every submitted build `v<MARKETING_VERSION>+<CURRENT_PROJECT_VERSION>`.

## Every release

1. `swift test` is green, and `Scripts/bake-catalogue.sh` leaves
   `Sources/FilmEngine/Catalogue` unchanged. CI enforces both.
2. `CHANGELOG.md` has an entry, and it is the App Store "What's New" text.
3. Archive and inspect:

   ```
   xcodebuild -project FilmApp.xcodeproj -scheme FilmApp -configuration Release \
     -destination 'generic/platform=iOS' -archivePath /tmp/Dye.xcarchive archive
   python3 Scripts/check-archive.py /tmp/Dye.xcarchive
   ```

   `check-archive.py` asserts the icon, display name, version, build number, device
   family, export compliance, category, privacy manifest, resource-bundle layout,
   dSYMs, launch background, and that no manufacturer mark reaches a surface a user
   can read. CI runs it unsigned on every app-touching change; run it signed here.
4. Regenerate the **Contact Sheet** if anything touched Stock naming or the engine,
   and look at it.
5. Work the manual matrix below on a real device. It cannot be automated and it is
   what a reviewer does in their first five minutes.
6. Validate and upload from Xcode Organizer. Confirm "Upload symbols" is on.
7. Tag, and push the tag.

## The manual matrix

Every row is verified on a device before each submission, or explicitly accepted as
a known limitation. Record the date and the device.

| Scenario | Expected |
| --- | --- |
| Cold launch | Reaches the welcome screen. No white flash. |
| Deny the Photos prompt | Export still completes, still shows the file, Share still works, and the sheet says it was not added to Photos and offers Settings. |
| Cancel the picker | Nothing changes. |
| Open an untagged photo | A plain-English message and an **Open as sRGB** button that works. |
| Open a truncated or corrupt file | A different message, about a damaged file. |
| Open a > 16 384 px panorama | A message about size, not a developer string. |
| Open an iCloud photo offline | Known limitation: no timeout and no cancel. See REL-33. |
| Background mid-Export | Known limitation: unverified. See REL-33. |
| Low storage mid-Export | The export fails and says so. |
| Rotate in every allowed orientation | No clipped controls, no unreachable targets. |
| VoiceOver: welcome → picker → browse → dial → compare → loupe → save a Preset → delete a Preset → Export | Every step reachable. Delete is an action, not only a swipe. |
| Largest Dynamic Type | The deck grows rather than clips. |
| Oldest supported device (A12, iOS 17) | Launches and renders. Never yet run. |

## First submission only

These are owner decisions and App Store Connect work, not code, and they gate the
listing. See the audit for the full argument on each.

- Business model — free, paid, or in-app purchase. **Undecided.**
- Privacy policy and support URLs for the App Store Connect record:
  `https://guillermo-rebolledo.github.io/dye/privacy/` and `.../support/`. Both pages
  are generated by `Scripts/build-site.py` from `FilmApp/Legal.swift` and served by
  GitHub Pages from `docs/` on `main`, so **they go live when this work merges** and
  need nothing bought or hosted. The app shows the same words on device without a
  network. Confirm both URLs load before entering them in App Store Connect.
- App Privacy questionnaire: "No, we do not collect data from this app." No tracking.
- Age rating, category, export compliance, name availability.
- Screenshots at every required size, captured against the current interface, using
  imagery whose rights are documented. Never Apple's simulator sample photograph.
- Listing copy. Say "modelled from published manufacturer datasheets" and
  "physically motivated". Never "accurate", "exact", "indistinguishable" or "true
  to" — the project's own accuracy audit does not support them. Keep every
  manufacturer mark out of the name, subtitle and keyword fields.
- Re-verify every platform claim in the readiness audit against the current App
  Review Guidelines. The audit ran without network access and marks each one
  *(recalled)*. This step is not optional.
